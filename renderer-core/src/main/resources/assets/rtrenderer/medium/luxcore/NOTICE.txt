api_emission.cu and primary_emission.cu are RTRendererAPI compatibility adapters.
The pinned homogeneous segment function still supplies transmittance unchanged; its
emission argument is zero for this adapter. The Java API instead requires the analytic
integral E * (1 - exp(-sigmaA * distance)) / sigmaA, including the zero-extinction limit.
The separate stable expm1/series adapter supplies that emitted radiance. This is a
public-semantics adaptation, not an unchanged LuxCore emission estimator or full integrator.

include/slg/textures/texture_densitygrid_funcs.cl, distributed as

boundary_transport.cu is RTRendererAPI production continuation glue around the pinned
segment and priority functions and these separate emission/density adapters. It
retains real Vulkan hit payloads and full final primary/T/E outputs. No upstream
segment or priority excerpt is modified by density integration.

camera_scattering.cu is an RTRendererAPI direct-single-scattering adapter. Vulkan
supplies the real light-connection radiance; the adapter preserves the public
interval/light work budgets and analytic camera-medium emission. It invokes the
unchanged pinned homogeneous segment function for RGB transmittance. Phase
evaluation in the retained Vulkan source stage follows the public Henyey-Greenstein
contract. This is not an unchanged LuxCore integrator or a claim of complete
multi-scattering/boundary support.

density_scattering.cu is a separate RTRendererAPI heterogeneous direct-scattering
adapter. It clips the camera segment to the density domain, retains the public
piecewise-constant midpoint density distribution and importance-sampled physical
positions, and passes those GPU states to Vulkan for real light connections and
surface visibility. Each returned connection is attenuated with the shared
LuxCore-derived density-grid sampler before native radiance accumulation. The
unchanged pinned segment implementation supplies RGB transmittance. Explicit
boundaries and additional volume bounces are not provided by this adapter.

optical_transport.cu adapts those Fresnel/reflection/transmission functions, the pinned
segment integrator and volume-priority functions to the public optical-interface

multiple_scattering.cu is RTRendererAPI finite-order homogeneous transport glue. It
uses the pinned exponential segment sampler and the public HG phase adapter, with
Vulkan supplying actual scene/light intersections. Its bounded state tracks RGB
mixture collision/survival probabilities and the public cumulative-distance budget.
Explicit boundaries and general material shading are not provided by this adapter.
boundary_packet.cu supplies bounded sorted-boundary packet processing and optional
terminal-radiance accumulation around the same pinned priority/segment functions.

pbr_transport.cu integrates ordered camera and direct-light boundary packets with
the same segment, density and priority components. Vulkan retains the public
surface BRDF and real geometry queries. This adapter currently admits opaque

adapter to density-grid optical mass and real light/geometry connections. It uses
the pinned segment sampler and the separate public HG compatibility adapter.
