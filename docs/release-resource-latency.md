# Resource latency and diagnostic modes

7.1.5 follows the N01–N09 handoff with a final native build, affected correctness, four-module packaging and publication. The user subsequently prohibited rerunning passed tests: 13 current-identity correctness checks passed; three scale combinations and 36 old performance windows retain their original identities. No final-DLL performance window was run. Performance optimization remains stopped. GPU/CPU budget misses and the missing final matrix remain explicit in [resource-latency.md](quality/resource-latency.md); MC frame rate belongs to consumer validation.

Dynamic packets produce one deduplicated mesh change plan before allocation and upload. Stable IDs, transaction revisions, change reasons and estimated input byte/triangle budgets link resource indexing, allocation, upload, clone/build/refit and GPU timestamp scopes. Index migrations for genuine topology changes remain explicit global work. Local material, texture, pose and attribute updates continue using persistent diffs and reverse dependencies. Texture patches update their alpha classification using only changed pixels; copying the CPU texture shadow and GPU copy-on-write work are reported separately from patch upload bytes.

Admission no longer performs instance-descriptor resets or repeated BLAS memory queries. Mesh/AS/command/event/staging pools are bounded. Reclamation transfers ownership through 32 fixed slots, without producer-side heap allocation or a worker mutex; a full queue rejects without moving ownership. Only completed graphics and compute readers permit retirement. Map-node frees and final driver-object destructors run on the release worker. `resourcePressure()` reports backlog, referenced byte estimates, peaks, rejection count and ages. These estimates are not physical VRAM.

Removing or replacing an instance also retains its detached node and mesh through both producer-queue completion points. A previous TLAS can still reference its BLAS address and bindless descriptors. Meshes still shared by a live instance are excluded from the reuse pool; last-instance removals can recycle safely. Failed-device garbage collection leaves queued resources to device teardown, preventing completion exceptions from escaping the application's destructor. A removed-device report is collected before rethrowing the first latched failure.

CPU diagnostic format 5 retains compatibility constructors and older snapshot decoding. It records resource identities, reasons, bytes, attempts, Windows thread IDs, modes and ordinals. An observer may register before creation and can inspect active initialization/resource calls before they return. Registration loss is separate from ring overwrite. Snapshot allocation is outside the recording mutex. GPU records preserve their issuing mode and resource association even if collected after OFF.

GPU CSV resource identities use the full unsigned 64-bit range. Java retains their bits in `long`; use `Long.toUnsignedString` when comparing their textual representation. High-bit IDs no longer terminate a DEEP snapshot with `NumberFormatException`.

SUMMARY does not execute ray atomics. An explicit work-statistics request is effective only in DEEP. OFF stops new diagnostics and drains issued samples within fixed bounds. A separate opt-in benchmark timestamp ring measures full GPU intervals in OFF without enabling product counters. Camera matrices continue to be submitted to RR every frame. PSOs are cached on demand from strict precompiled variants, never compiled as a runtime fallback.

The production shader removes component-wise divisions from conservative support rejection and skips shadows only for an exactly zero contribution. Source shape, attenuation, deterministic GI samples, quality and RR remain unchanged. These edits require numeric/oracle validation; their speedup and the 4 ms P95 target are determined by measurement, not by source inspection.

`tools/Test-ResourceLatency.ps1` is the serial, 10 GiB-bounded correctness and performance runner. Under the final no-rerun instruction it is no longer run for passed cases. The one timed-out attribute/topology case passed its single JFR diagnostic retry with unchanged assertions; the first timeout cause remains unknown. Historical GPU windows and current correctness runs retain separate identities. No FG/MFG, consumer game files or player directories are involved.

Final outcomes, actual runtime hashes, remaining unknowns and comparison limitations belong in [resource-latency.md](quality/resource-latency.md). The API fixture does not certify MC frame rate or establish the cause of an unobserved GL stall. GitHub receives source code and the version tag only; binary artifacts are published to Maven Local. No release binaries, raw-test attachments or Central publication are uploaded.

`tools/Collect-ResourceLatencyEvidence.py --reuse-reviewed-evidence` preserves prior passed evidence under the user no-rerun instruction and records zero final-DLL performance windows. `tools/Verify-ResourceLatencyRelease.py --allow-reused-acceptance` verifies package bytes and metadata while retaining that explicit missing acceptance; it does not certify performance. The default strict verifier still requires all 36 final-DLL windows with the complete request boundary. `--local` compares Maven Local files without rendering. The identity record remains outside the runtime ZIP to avoid a self-hash cycle.
