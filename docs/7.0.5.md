# RTRendererAPI 7.0.5

7.0.5 修复已确认的帧内短任务等待、材质名称引发的重复着色器准备、外部共享输出尺寸截短，并提供可按帧下钻的诊断。公共 renderer-api ABI 沿用 7.0.4；四模块统一版本 7.0.5，Java 25。保持 RR Quality／1 SPP 的输入和画质语义，不通过减少灯光、几何或新帧数取得收益。

帧任务按当前 worker 数及元素量分块，少于 128 个元素直接由调用线程执行。并行批次有独立完成条件、异常与立即完成通知；8ms 超时仅用于 owner 线程处理窗口事件，不是完成轮询下限。实例、子实例及灯光相关派生数据在同一 managed scene generation 内复用，资源、姿态及材质变更使其失效；非托管动画场景保留逐帧重算。

当前 StandardBSDF 的颜色、纹理、alpha test 和透射都属于运行期材质数据。7.0.5 用实际着色器排列决定稳定导出名称，预置完整动态 StandardBSDF 和 any-hit 导出；opaque 几何仍按原 traversal flags 跳过 any-hit。新增／替换材质无需临时编译另一个同义着色器，也无需先显示一种简化材质。PSO 初次创建、配置重建及 resize 仍有准备成本，不承诺这些操作零等待。

发布包的 ShaderDynamic/Bin/dxil/bundle.json 包含完整排列、命令、源码 SHA-256、编译器 SHA-256 和 pipeline identity。支持矩阵包括原生、RR、SR、SR＋NRD、场景解析灯光、透明 coverage、关闭介质、六档精确光学接口预算及原有回归配置。开发者自改宏／HLSL 走既有热重载路径，不属于发布包的预编译矩阵。RTR_RTXPT_REQUIRE_PRECOMPILED=1 在制品缺失／陈旧时给出完整缺失路径；安装时校验发行档案指纹。

外部呈现使用请求的输出 extent，隐藏窗口仅承载平台上下文，不决定输出像素数，不抢焦点。最大单边 16384，超限在 native 场景修改前拒绝；实际可分配大小仍受设备资源限制。原生独立窗口沿用其窗口尺寸策略。共享帧继续按 ready／completion timeline 交接，resize／关闭先退休旧代。主动弃用尚未消费的帧时，退休等待实际 shared fence，避免 NVRHI 较早的提交 fence 造成清理竞态。

```java
var access = renderer.extension(RtxptDiagnosticAccess.class).orElseThrow();
access.diagnosticLevel(RtxptDiagnostics.Level.DEEP);
var cpu = access.diagnosticSnapshot();
var gpu = access.diagnosticGpuSnapshot();
access.diagnosticLevel(RtxptDiagnostics.Level.OFF);
```

RtxptRenderer 和 RtxptComposedRenderer 都提供上述诊断视图，组合路径不暴露隐藏 producer 的推进／窗口控制。默认 SUMMARY；DEEP 增加 worker、caller、消息泵和逐命令 GPU 范围。OFF 停止新增 CPU／GPU 事件、provider timer 和显式内存 census；已经提交的查询以非阻塞方式收尾。gpuTimingsEnabled=false 仍禁止 GPU 查询，DEEP 不覆盖调用者的禁用选项。环境变量 GPU 采样仍可在 SUMMARY 显式启用，OFF 优先。

CPU 使用 8192 条有界滚动事件，保存 sequence、revision、thread、stage、batch、数量、任务数、inclusive／self；self 只扣本线程嵌套子范围。超过 50ms 时另保留最近慢帧最多 2048 条事件，覆盖数显式返回。flags 的 1 表示 D3D12 queue Wait 的 CPU 入队成本，2 表示异常退出，4／8 表示 shader cache hit／miss。TASK_WAIT.tasks 是进入等待时实际 pending，DISPATCH.tasks 是批次分块数。快照在调用者显式拉取时分配，无热路径同步写盘。

GPU 保存每队列命令范围、包含关系、sequence／revision、pending 和 dropped／overwritten；完成范围上限 4096，采样 interval 可见。GPU timestamp 包含调度／抢占，不能称为 shader 忙时。既有 provider 总 GPU interval 在 CPU 录制前开始，可能包含队列空档；下钻请使用 diagnosticGpuSnapshot。事件输出和 opt-in memory census 使用有界异步 writer。宿主 OpenGL 内部 wait／copy／flush 不在 API 的可观察边界内。

首次加载、增量更新、稳态和 resize 应分别取样；submitStages 是累积 inclusive 计数，必须同一窗口做差，不能直接减入某个 CPU scope 的 self。快照给出 FRAME 的 P50／P95／P99／max 和 >50／100／1000ms 次数，分阶段可按 stage 自行分组。结果、测试范围与制品指纹见 [定向验收](quality/rtxpt-frame-preparation-705.md)。匹配的 PDB 另以 renderer-rtxpt 的 native-symbols ZIP classifier 随 Maven Local 制品交付。
