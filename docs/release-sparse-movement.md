# 稀疏光源移动更新与批量上传

当前兼容修复候选为 `7.2.0-rc.8`。真实宿主的直接光路线已停用 GI 和 RR，但移动时稀疏区域更新与上传仍阻塞提交：保留慢组中区域更新达到 80.4565 ms，同批次还出现 8,761～16,345 次 staging 小操作。初始 GPU 占用 54%，这份数据用于定位内部工作，不能判定绝对 FPS 收益。

上传此前只合并连续节点，区域节点最多跨四个未变节点；散落哈希／BVH 变化因此变成上万次 `writeBuffer`，每次重复执行 staging 获取、复制、屏障和命令录制。新候选在 4 KiB 间隙内合并来自同一 CPU 权威镜像的范围，每次写入仍不超过 1 MiB，不新增全池重包。实际复制的中间未变字节计入原有上传字节统计。

`RTR_RTXPT_DISABLE_SPARSE_UPLOAD_COALESCING=1` 可恢复原细碎范围，供宿主同入口对照。控制只用于通用执行器诊断，不包含宿主特定类型、尺寸或场景判断。CPU 散落夹具中，9,040 次写入降为 16 次（−9,024，−99.82%）；实际上传从 578,560 B 增至 16,749,568 B（+16,171,008 B，+2,795.05%）。这是命令开销与复制带宽的交换，不能冒充 FPS 收益，最终还须由宿主记录实际场景字节数和耗时。

同时修复诊断快照每次无条件预留四组最大慢事件容量的问题。改为先捕获本次快照的事件上界，再在记录器锁外分配；并发覆盖只会减少最终事件，不会触发复制锁内扩容。已消费慢组的 CPU 夹具从固定预留 58,552,792 B 降到 1,769,672 B（−56,783,120 B，−96.98%），保留全部事件、cursor、覆盖和截断协议。此项只说明临时 native 容量，不能代替 MC 进程峰值测量。

稳定源叶前沿方案已撤回生产源码与默认运行目录，没有保留实验分支或开关。该方案的 54 份 raw、54 份真实 RR 输出均与 rc7 逐字节一致，但 25,000 源阶段 0 的区域 links 从 339,108 增至 760,345（+421,237，+124.22%），packed 数据从 19,922,944 B 增至 26,214,400 B（+6,291,456 B，+31.58%），source-node 访问从 1,818,747 增至 3,075,140（+1,256,393，+69.08%）。固定 GPU buffer 预算没有增加；packed 字节不是物理 VRAM。这些确定代价不符合本轮降低内存峰值的要求，失败证据保留在 `build/reports/sparse-movement/rejected-frontier/`，不得将其 CPU 更新减少算入最终版本收益。

最终仍采用原 treelet 区域前沿，其树旋转／成员重建造成的 `SPARSE_REGIONS` 开销尚未解决。本批只修复细碎上传放大的重复工作与诊断临时预留。

撤回后的 25,000 源／2,198 probes CPU 检查、诊断完整性／OFF／并发覆盖检查通过；最终 DLL 的 54 份 raw、54 份真实 RR 输出与 rc7 逐字节一致。区域 roots、cells、links、packed bytes、各类射线和节点访问逐阶段与 rc7 一致。24 帧真实上传夹具覆盖增长 128→4,096、删除 3,072 项及反复移动，staging 请求 3,843→1,726（−2,117，−55.09%），请求字节 23,202,516→24,238,676 B（+1,036,160 B，+4.47%）；源记录上传均为 675,840 B（差 0，0%），索引上传 19,480,256→20,516,416 B（+1,036,160 B，+5.32%）。最大写入均为 1,048,576 B（差 0，0%），最大 staging 分配均为 2,097,152 B（差 0，0%）。此处 staging 数是夹具全部记录到的 staging 请求，上传字节计数包括合并间隙的实际复制。

25k 光源 raw 夹具阶段 2 的区域更新上传 1,033,024→2,138,944 B（+1,105,920 B，+107.06%），需要与宿主的命令耗时一起判断，不能藏在累计初始上传中。最终输出／上传对照合并 Job 峰值 2.611 GB，最终 DLL 构建峰值 0.814 GB；单位为脚本将 peak process-tree commit 除以 1e9 后打印的十进制 GB，保留三位小数，没有字节级精度。没有单独测量旧／新 Job 峰值，不能据此宣称整体内存降低。诊断临时容量减少有独立代码与 CPU 检查证据。

四模块制品核对与宿主同入口移动验证继续进行，不声明 FPS、时延或长尾收益。证据目录为 `build/reports/sparse-movement/`，原始变化汇总为 `measurements.json`，发布身份收据为 `receipt.json`；不重标旧 DLL 的完整矩阵结论。
