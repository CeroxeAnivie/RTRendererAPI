# RTRendererAPI 6.0.3

6.0.3 fixes driver pipeline-cache persistence for every retained-scene program and the
bootstrap pipeline. Rendering algorithms, material and medium semantics, shader quality,
public Java entry points and the 6.0.2 ABI remain unchanged.

Previously all GPUScene programs accumulated in one device cache. Once the resulting
blob exceeded 64 MiB, extraction silently skipped persistence, allowing repeated expensive
driver compilation. Caches now use SHA-256 identities over complete ordered stage binaries
and the descriptor/group ABI, scoped to vendor, device and driver pipeline-cache UUID.
SDR/HDR, custom programs and the optional shadow-service stage remain distinct.

Opaque driver payloads have an independently versioned envelope, length and SHA-256 checksum.
Truncated, corrupt, foreign-driver and oversized payloads are rejected before driver creation.
Writes replace complete files atomically where the filesystem supports it. Concurrent writers
publish complete compatible entries; cache I/O failures remain optional and emit bounded warnings.

Default bounds are 128 MiB per payload, 512 MiB of managed cache files and 128 entries.
Oldest managed entries are evicted after successful publication; unrelated files and old aggregate
caches are left untouched. A renderer loads only its own program's entry, rather than the complete
historical collection. Optional JVM properties (never application-specific repository settings):

- `top.ceroxe.rt.pipelineCache.directory`: cache directory.
- `top.ceroxe.rt.pipelineCache.maxEntryMiB`: 1–1024, default 128.
- `top.ceroxe.rt.pipelineCache.maxDirectoryMiB`: at least entry budget + 1, at most 16384; default 512.
- `top.ceroxe.rt.pipelineCache.maxEntries`: 1–4096, default 128.

Cache misses still require driver compilation. This release does not claim to remove the
first-ever compilation cost of a new program. Shader or driver changes select a fresh identity.

Delivery is GitHub and the local Maven staging repository only; no Maven Central publication.
The historical 6.0.0 and 6.0.2 ABI snapshots are retained without modification.

Validation on NVIDIA GeForce RTX 5080 Laptop GPU: root `check`, demo `check`, native
precompiled SDR/HDR exact pixels, application-data generations and frame-slot reuse, followed by
complete local Maven publication passed (163 tasks). Cache tests cover stage/ABI identity,
device separation, round trips, corrupt/truncated/oversized payloads, preservation of valid entries,
entry-count and byte-budget eviction, and protection of unrelated files. Vulkan validation
reported no warning, error or dropped messages in the native precompiled gate.
