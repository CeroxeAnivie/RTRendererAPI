# RTRendererAPI 7.0.2

7.0.2 为通用 RTXPT retained scene 增加资源增量更新和大规模直接光照采样，并修复实例结构变化及窗口等待的问题。公共 `SceneTransaction`、场景版本、帧序列与介质合同不变，`renderer-api` ABI 与 7.0.0 相同。此前的支持边界见 [7.0.1](7.0.1.md)。

依赖为 `top.ceroxe.rt:renderer-api:7.0.2` 和可选的 `top.ceroxe.rt:renderer-rtxpt:7.0.2`。Demo 为 `RTRendererAPI-HexBallDemo-7.0.2.jar`、`RTRendererAPI-MediumDemo-7.0.2.jar`。源码交付 GitHub，制品发布 Maven Local。

## 资源更新

首次提交和显式 `resetScene` 使用完整导出／加载。后续网格、实例、材质和纹理修改只翻译变化的资源及其依赖，使用同一原生场景的 importer、描述符分配器和纹理缓存。材质保持 GPU 槽位，只上传变化的数据；兼容尺寸／格式的纹理更新复用原有 GPU allocation。单个网格更新只构建受影响的 BLAS，实例增加／删除共享已有 BLAS，必要时更换 TLAS。

资源更新在提交帧前发布。目前采用保守的全队列 fence 等待，再修改或退休旧资源；因此不会与旧一代 GPU 工作重叠。原生提交失败会明确关闭该 session，CPU 校验失败保留原场景。临时翻译文件随依赖退休，关闭时清理整个目录。此路径仍使用稀疏 glTF 作为原生导入格式，并非零拷贝资源 ABI。

## 大规模光照

`SCENE_ANALYTIC` 在小集合下保持完整求和；超过 `exactPointLightLimit + 1`（包括环境太阳槽位）后使用 GPU 空间灯树。每个 shading receiver 执行配置的完整 light samples 次采样，每次访问平衡树的一条路径。位置、方向、颜色、强度、范围、聚光锥和阴影开关仍由原始灯记录参与求值。

每个分支使用空间／功率重要性与均匀分布混合，弱光源也保持非零选择概率，并按实际选择概率补偿。所有已接受灯光都有叶节点；不截断距离、不保留最近 N 盏。实际灯光编辑重建索引；只有环境变化时复用排序结果并只更新太阳记录和祖先路径。`BACKEND_DEFAULT` 继续使用上游采样器。

## 窗口和诊断

实例拓扑／光追 hit group 改变时更新 shader binding table，避免新实例沿用旧表。交换链按后台缓冲区 fence 值确认完成，等待过程中处理窗口消息；shader 编译任务等待、resize／readback 的 GPU 等待也处理创建线程的消息。无法完成的 GPU 等待有超时，frame retirement 失败会向 Java 传播。

`RtxptAccess.retainedUpdateMode()` 报告本次提交走初次发布、显式重置、资源 delta、transform 或 lighting 路径。`retainedUpdateTimings()` 给出资源翻译、BLAS／TLAS、索引构建和同步等待的累计计数；recording 时间是 CPU 时间。GPU interval 来自资源命令前后的队列时间戳，可能包含 BLAS 压缩期间的 CPU 提交间隙，不能当作纯 GPU 忙碌时间；查询只收集已完成的样本。`lightSamplingStatus()` 区分上游、完整求和和灯树，并报告表示的灯数／索引节点数。设置进程环境变量 `RTR_RTXPT_LIGHT_STATS=1` 后，可显式读取上一原生帧的 shading receiver、实际采样、树访问和 shadow test 计数；该读取会同步 GPU，不能放进性能帧循环。

验证与定量对比见 [7.0.2 验收记录](quality/rtxpt-retained-702.md)。普通截图仍为 SDR；线性 HDR 读取仅用于内部验收，不新增公共逐帧 readback 合同。
