# 7.2.1：统一版本与项目清理

四个 renderer 模块及示例依赖统一为 7.2.1，保留 rc.10 已交付的资源链、宿主输入契约、稀疏移动、上传生命周期和显式光源可见性能力。本次不增加新的性能优化候选。

## 目录约定

- `renderer-*`：生产源码、资源与维护中的测试；`demos`、`examples`：正式示例。
- `tools`：构建、SDK、验收与证据分析工具；删除已无调用方的一次性诊断工具。
- `docs/quality/data`：已归档的正式验收记录，JSON/CSV 具有版本与制品身份，继续保留。
- `build`、模块 `build`、缓存、崩溃日志和一次性实验输出不进入 GitHub。历史失败证据与本次回归原始输出移到仓库外保留。

## 回归与交付

新增维护入口 `fullRegression`，覆盖完整发布闭包、全部注册的 Java self-test 和 RTXPT C++ 契约；补接此前只有源码而没有 Gradle 入口的专项。纯 benchmark 和需要人工指定工作量的独立 GPU 内存调查探针不自动运行。扩展示例在测试前从当前 shader SDK 重新生成，避免残留 DXIL 的 ABI 与当前 DLL 不一致。

首轮回归暴露并处理以下阻塞，最终复验结果待补：

- 修正 `SparseLightSource` 的 Javadoc 转义，恢复文档制品构建。
- 关闭 renderer 时，临时目录已被外部清理不再报错；其他 I/O 错误仍保留，并补充重复关闭检查。
- Vulkan 吞吐测试的首帧使用既有总时限等待首次准备；首个完成之后仍保持原 30 秒无进展限制，不改变工作量或计时范围。首次超时的具体原因尚未证实，复验附带启动 JFR。
- 资源矩阵同时核对 build/refit，要求恰好一个几何 BLAS 更新及其余 255 个保留；alpha texel 更新遵循已有的候选着色器覆盖契约，不再错误要求重建几何 BLAS。
- OFF 检查不再自行切回 DEEP；稀疏上传按实际局部变更数量及已存在的 4 KiB 合并间隙约束真实复制字节，不把额外复制字节从统计中扣除。
- 混合 geometry/alpha 更新继续检查开孔与恢复的真实像素，同时要求只更新一个几何 BLAS、保留另外两个；记录实际 build/refit 数量。
- raw/analytic 的增量与全量参考双方采用同样的 64 SPP，避免把光源槽位顺序改变后的单样本差异直接当作能量偏差；原有块误差与全局均值门槛不变，是否消除首轮失败以复验结果为准。

2026-11-06 用户要求停止测试，先合并验收窗口；CPU/GPU 回归、性能测试和基准均已停止，本次只做编译、静态检查及任务图预览，不恢复全量回归。此前定向复验中，Vulkan 吞吐、Advanced 和当时的 11 项 C++ 契约通过；Budget 在 12/17 后的 `exact-2` 报 `Budget window stays open`，后续专项未执行。新增的 `upload_pool` 契约不在该轮 11 项记录内。以上均保留当时源码和制品身份，不能作为当前提交的完整通过结论。磁盘空间耗尽、临时目录消失和链接失败的原始记录继续保留。

## 验收窗口合并

- 新增 `:renderer-rtxpt:rtxptSharedLightingNativeSelfTest`，五个相同 `config(4)` / 独立 native-lighting 专项共用一个 Renderer、原生设备和窗口。默认覆盖原生光照矩阵 5 场景、属性矩阵 3 场景、资源矩阵、混合资源更新，以及光源可见性 16 场景：原来合计 26 次初始化改为 1 次。这个数字表示初始化次数，尚未实测耗时收益。
- `fullRegression` 和 `verifyApiClosure` 使用该共享批次，不再重复执行这五个旧入口；报告包含明确的 `task → executedBy` 覆盖关系，共享批次另外输出逐专项成功／失败记录。原入口保留用于单独定位；各矩阵单独运行时也复用自己的窗口。
- 每个场景继续 `.resetScene()`；帧号、场景 revision、属性 generation 全局递增。lookup、application data、统计开关和诊断拆分恢复默认，计数按场景增量核对，避免投影 lookup 或 DEEP 状态污染后续场景。所有原像素、CPU oracle、资源保留、时序和真实新帧断言保留。
- 光追预算、初始化资源配置不同的场景仍单独建 Renderer；关闭重开、生命周期、真实 RR、窗口响应、压力和打包消费者验收继续保持独立，不通过改生产生命周期绕过公开的重建契约。`timings`、`topology-coverage` 和资源 `tail` 的定向入口继续保留，不因本次合并扩跑矩阵。
- 检查结果：测试源码编译通过；完整任务图 dry-run 通过，共享入口出现一次，五个旧任务均未重复接入；原断言与采样保留，UTF-8 和 diff 检查通过。所有日志留在仓库外。
- 本次没有执行共享批次或其他测试，因此 `exact-2` 及其余首轮失败项仍未最终复验，完整 7.2.1 验收未完成。后续恢复测试时从共享批次开始，不能把编译通过当成功能验收。
