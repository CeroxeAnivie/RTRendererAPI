# 7.2.1：统一版本与项目清理

四个 renderer 模块及示例依赖统一为 7.2.1，保留 rc.10 已交付的资源链、宿主输入契约、稀疏移动、上传生命周期和显式光源可见性能力。本次不增加新的性能优化候选。

## 目录约定

- `renderer-*`：生产源码、资源与维护中的测试；`demos`、`examples`：正式示例。
- `tools`：构建、SDK、验收与证据分析工具；删除已无调用方的一次性诊断工具。
- `docs/quality/data`：已归档的正式验收记录，JSON/CSV 具有版本与制品身份，继续保留。
- `build`、模块 `build`、缓存、崩溃日志和一次性实验输出不进入 GitHub。历史失败证据与本次回归原始输出移到仓库外保留。

## 回归与交付

新增维护入口 `fullRegression`，覆盖完整发布闭包、全部注册的 Java self-test 和 RTXPT C++ 契约；补接此前只有源码而没有 Gradle 入口的专项。纯 benchmark 和需要人工指定工作量的独立 GPU 内存调查探针不自动运行。扩展示例在测试前从当前 shader SDK 重新生成，避免残留 DXIL 的 ABI 与当前 DLL 不一致。

首轮回归暴露并处理以下阻塞，最终复验结果待补：

- 修正 `SparseLightSource` 的 Javadoc 转义，恢复文档制品构建。
- 关闭 renderer 时，临时目录已被外部清理不再报错；其他 I/O 错误仍保留，并补充重复关闭检查。
- Vulkan 吞吐测试的首帧使用既有总时限等待首次准备；首个完成之后仍保持原 30 秒无进展限制，不改变工作量或计时范围。首次超时的具体原因尚未证实，复验附带启动 JFR。
- 资源矩阵同时核对 build/refit，要求恰好一个几何 BLAS 更新及其余 255 个保留；alpha texel 更新遵循已有的候选着色器覆盖契约，不再错误要求重建几何 BLAS。
- OFF 检查不再自行切回 DEEP；稀疏上传按实际局部变更数量及已存在的 4 KiB 合并间隙约束真实复制字节，不把额外复制字节从统计中扣除。
- 混合 geometry/alpha 更新继续检查开孔与恢复的真实像素，同时要求只更新一个几何 BLAS、保留另外两个；记录实际 build/refit 数量。
- raw/analytic 的增量与全量参考双方采用同样的 64 SPP，避免把光源槽位顺序改变后的单样本差异直接当作能量偏差；原有块误差与全局均值门槛不变，是否消除首轮失败以复验结果为准。

按本次明确授权重新执行全量回归，覆盖确定性契约、major-7 ABI、Vulkan/NVIDIA/RTXPT 原生路径、真实 RR、打包运行、发布消费者与分发包哈希。重任务串行并保持 10 GB Job 上限。磁盘空间耗尽及清盘期间临时目录消失的首轮失败保留原始记录，不计为通过。

历史完整 GPU P95 4 ms 目标未达标；本轮功能回归通过不改变该结论，也不把旧性能矩阵改标为 7.2.1。
