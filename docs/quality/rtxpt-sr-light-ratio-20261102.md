# RTXPT SR 暗灯噪声复现与曝光控制

## 本轮已确定的范围

最新打包 Demo 日志明确包含 `RTXPT native small-point lighting ACTIVE`，且缓存 DLL 与构建 DLL 的 SHA-256 相同。
不是把以前的小灯策略漏打包，也不是切 SR 时将它禁用。SR、无 RR／NRD／SHaRC、1 SPP 的实际状态已留证。

之前为压过曝，只将三盏彩色点光源降至原强度的四分之一，环境光与太阳未变。这改变了确定性点光与随机环境采样的相对比重。
本轮用完全相同的静止／运动／停止序列按光源拆开，不修改生产积分器；以下测试均关闭 FG，输出 2560×1440，输入 1485×835。

| 隔离场景 | 固定上方底板 ROI 帧间 RGB MAE /255 |
|---|---:|
| 四分之一点光、完整环境、玻璃 | 1.640784 |
| 四分之一点光、完整环境、金属 | 1.620519 |
| 四分之一点光、移除太阳、玻璃 | 1.179728 |
| 四分之一点光、移除全部环境、玻璃 | 0.940505 |
| 仅直接照明、完整环境、玻璃 | 1.512672 |
| 仅直接照明、移除全部环境、玻璃 | 0.005330 |

由此可以确定：已覆盖的少量点光直接贡献稳定；金属与玻璃的底板波动接近，不能将这次回归只归给玻璃或运动向量。
环境照明和间接路径仍会产生采样噪声。移除光源、删除反弹仅用于隔离，不能作为生产修复或 FPS 验收。

点光恢复原强度、零曝光偏移时该 ROI MAE 为 0.837041，但亮度也明显提高，tone mapping 压缩与截断会改变这个指标。
不能仅凭更亮画面的绝对 MAE 较低就宣称渲染器降噪成功。

## 保留的正确性与显示改动

- 继续采用已验证的小灯逐灯求和与 SR；不擅自开启 RR、NRD、SHaRC。
- 恢复原点光强度，避免为了改亮度改变光照比例。
- 增加薄的 `RtxptAccess.setExposureCompensation(float)`，直接设置上游 `ToneMappingParams.exposureCompensation`。
- 玻璃 Demo 使用 -1.5 EV 控制亮度；它是场景展示设置，不是任意场景的通用采样／降噪修复。
- 回读实际曝光，验证首帧前设置、场景重载和缩放生命周期；有限值检查保持明确。

曝光不增加渲染阶段，不降低分辨率、SPP 或路径深度。具体帧率仍以最终运行记录为准，不能仅凭代码宣称已经证明零性能损耗。

## 尚未解决

少量 delta 光逐灯求和不能替代任意环境光、面积光、多灯与间接反弹的采样重用／降噪。纯 SR／1 SPP 下的通用噪声修复尚未完成。
后续必须保持灯光与材质不变，用成熟后端提供的能力按正确输入接入，并同时检验内部细节、运动历史与完整帧性能。
不得重复用切 RR、加降噪或改变曝光来冒充同配置的通用根因修复。

原始 `sr-*-v23` 日志／配置在 `data/hexball-native-20261101/`；截图在忽略的 `build/reports/hexball-quality/`。
使用 `tools/Analyze-HexBallLightProbes.py` 可重新计算固定 ROI 波动、平均亮度与高亮通道比例。
