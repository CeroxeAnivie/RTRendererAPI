# RTXPT 无降噪颜色合成修复

用户验收：纯 SR 已追上旧路径开启诊断的帧率，但画质仍不合格；暂停 FPS 主线，先修画质。

## 已证实的错误

`quality-reuse-raw-v9` 虽然 runtime 报告 ReSTIR DI 启用、正常关闭，但截图明显变暗。仅检查功能开关和 exit 0 不足以通过画质验收。

沿上游代码能确定直接光丢失的具体顺序：

1. `RTXDI/DIFinalShading.hlsl` 无降噪分支向 `u_OutputColor` **累加** ReSTIR 直接光；`GIFinalShading.hlsl` 同样使用输出颜色累加。
2. `Sample::PostProcessAA` 随后执行 `NoDenoiserFinalMerge`。
3. `ProcessingPasses/PostProcess.hlsl` 的该 pass 用层辐射 **赋值覆盖** `u_OutputColor`，因此刚累加的 ReSTIR 光照丢失。单纯调采样、滤波、锐度都不能修复这个问题。

修复：仅在无降噪 RTXDI 路径中，把已有原生 merge 提前到主追踪之后、RTXDI 之前；后置 merge 在该路径中跳过。保持每帧唯一一次合并，SR/TAA/无 AA 都读取当前完整颜色。NRD/RR 和未启用 RTXDI 的顺序不变。

这不代表用户提出的所有模糊已解决，也不把增加降噪冒充同配置修复。原始 SR、原生 ReSTIR+SR 和 RELAX+SR 分开留图验证。额外 32 SPP 模式仅用于画质参照，不能用于宣称 1 SPP 帧率或验收结果。

## 上游对照

- 固定 RTXPT 1.9.0 源码的 `Docs/Design.md`、RTXDI final shading 和 NRD integration。
- NVIDIA NRD 官方 README 明确 RELAX 面向 RTXDI；候选采用上游重采样与降噪机制，不实现第二套算法。
- DLSS jitter 按本项目实际相机射线的符号推导。新路径的采样偏移与旧路径相反，不能直接照搬旧路径常量负号。

## 已完成的硬件对照与默认策略修正

所有对照输出 2560×1440，输入 1485×835，FG 关闭。原始 SR、RELAX+SR、原生 RR 都是 1 SPP；独立参照为 32 SPP，不能用于 1 SPP 性能结论。每组包含静止 164 帧、运动 120 帧、停止运动 80 帧，scene export 都只有一次，正常完成生命周期。

1. 修复 RTXDI 被覆盖后直接光恢复，但原始 SR 的静止帧间 RGB MAE 仍约 2.71/255（之前约 2.74/255）。这项正确性修复不能宣称解决所有噪点。
2. RELAX+SR 的静止帧间 MAE 约 0.066/255，数值稳定，却抹宽阴影并漏掉较淡的彩色阴影。此前仅用噪声稳定和外轮廓判断“清晰”是不充分的。
3. 采用同分辨率原生 RR 后，上球青色阴影的 10%–90% 边界中位宽度由 **27.8769 px** 收窄到 **2.5525 px**；32 SPP 参照为 **2.4910 px**。17 条固定扫描线、四帧均值，不缩放或锐化截图；阴影对比度没有降低。
4. 对相同确定性运动第 119 帧，场景 ROI 与 32 SPP 参照的 RGB MAE 从 **5.5169/255** 降到 **3.3617/255**。这个指标包括残余噪声和估计偏差，不能称为“拖影完全为零”。玻璃球同样完成静止/运动/停止三阶段截图。

Demo 默认改回上游联合降噪/重建 **DLSS RR**，不叠加 standalone RELAX；默认 2× FG 和原生 SHaRC 策略保留。`--original-settings` 仍是明确的纯 SR 对照，RESPONSIVE API 仍可选原生 RELAX。**这是默认画质路线修正，不是纯 SR 同配置性能优化。** 此处的图像计时包含截图读回，不能用它计算正常游戏 FPS。

新增 `Analyze-HexBallReconstruction.py`：必须同时验收内部阴影边界、对比度和静止噪声，避免再次用“很稳定的一团糊”通过画质验收。此项回归覆盖一条指定阴影边界，并不冒充所有材质和运动条件已完全验收。

## 用户追加性能约束：撤回 RR 默认切换

用户明确不能为了清晰度加入别的功能，导致 FPS 再次低于旧路径。因此撤回以上 RR 默认切换；已测的 RR/RELAX 仅保留为画质对照，不算这项任务通过。

当前 Demo 默认与已取得约 222 FPS 的路线保持同一基础策略：纯 SR、1 SPP、无 standalone NRD、无 RR、无 SHaRC；默认 FG 仍按原 Demo 为 2×，测试明确关闭。渲染 API 仍可显式选择其他高级功能。

后续质量候选必须同时满足画质与该配置的性能要求。保留确定性的 RTXDI 颜色合成修复。增加仅测试用 `direct` 模式（单次表面直接照明、无间接反弹），区分采样噪声来自直接照明还是后续反弹；该删减模式绝不能冒充正常场景性能或画质验收。

硬件结果：默认纯 SR 原配置静态 ROI 帧间 MAE 为 **2.741416/255**；去掉全部间接反弹仍为 **2.980994/255**。直接光本身就足以产生大量颗粒，不能把问题只归给间接反弹。打包 JAR 也已确认实际无 RR、NRD、SHaRC；与此前原始 SR 的同一指标 2.741426/255 一致。

## 当前隔离候选：小规模 delta 点光逐灯求和

只通过诊断开关 `RTR_RTXPT_DIAGNOSTIC_SMALL_POINTS=1` 启用，默认不启用。

- 依据 PBRT-v3 的成熟 `UniformSampleAllLights / EstimateDirect` 逻辑：点光源是 delta 分布，逐盏灯求和避免随机抽灯的颜色方差。来源：https://github.com/mmp/pbrt-v3/blob/master/src/core/integrator.cpp 。这不是后处理或降噪。
- 仅在解析光数量不超过四个时覆盖零半径点光，其余面积光、方向光、环境与间接反弹保留原始估计和 PDF。被覆盖点光不再从随机 NEE 重复加入，保证不重复计能量。
- 复用 RTXPT 的 `PolymorphicLight::CalcSample` 与 `ProcessLightSample`，不另写 BRDF、阴影、介质可见性或合成算法。
- 同时使用已有原生 power sampler，避免为这个少量灯的场景维护整套屏幕反馈采样；不会启用 NRD/RR/ReSTIR/SHaRC。
- 不以删减反弹、降低内部尺寸、改变 1 SPP、降低输出分辨率换成绩。必须图像正确且整帧性能不降才可成为默认；失败保留证据并撤候选。

## 已测候选收益与通用范围修正

v16 对照两轮初始 GPU 都为 0%。2560×1440 输出、1485×835 输入、1 SPP、纯 SR、FG off，30 秒完整窗口平均：原始路径 212.953667 FPS，点光候选 242.158915 FPS，增加 13.71%。v15 同一确定性画质序列静止 ROI 帧间 RGB MAE 从 2.741416/255 降到 0.779824/255，减少 71.55%。这些数字是弹球场景的实测，不能当成全场景收益。

用户要求是渲染器级通用修复。现在按内容自动选择：原始 1-SPP SR、无降噪/重采样/缓存、至多四个解析光、有零半径点光或聚光、没有发光材质时使用原生 power sampler 与 delta 求和；环境光不计入解析光上限。其余场景保留上游可扩展采样，不能把 fallback 说成噪声已经解决。场景加载时重算资格，退出分支恢复原 NEE 策略，不在每帧扫描材质。不再依赖 Demo 名称或材质数量特判。诊断开关 `0` 可强制原始对照，未设置时自动选择。

### 更广泛的明确错误：方向光样本语义

固定版本 `PolymorphicLight.hlsli::DirectionalLight::CalcSample` 将光线方向直接存入 `Position`；普通 `PathTracerNEE.hlsli::GenerateLightSample` 却一律执行 `Position - shadingData.posW`，把它当世界坐标。这样光照方向与遮挡射线长度错误地依赖物体世界位置。官方同版本 `IntroRTXDIBridge.hlsli::RAB_GetLightDirDistance` 已有正确逻辑：方向直接使用样本向量，阴影距离为 1e6。

桥接构建脚本据此修正普通 NEE 的方向光分支，点光、聚光、面积光、环境光的坐标处理保持原生。`RTR_RTXPT_DIAGNOSTIC_DIRECTIONAL_CONTROL=1` 仅用于复现错误的 A/B 对照。通用回归覆盖四点灯、聚光、多灯、发光网格、环境、方向光、玻璃/嵌套吸收混合；整体平移场景和相机检查方向光不变性，并留四帧截图与 32-SPP 独立参照。此处是待实测的验证设计，不提前宣称通过。

实测修正：原始与修正的 sun 场景截图一致，平移 MAE 均为 0.024151/255。原因是 Advanced 路径默认将方向光烘进环境图，`CollectAnalyticLightsCPU` 只收集点光/聚光。这是可确定修正的潜在分支错误，**不是当前模糊的现行根因，没有实测画质收益**。保留证据，不把代码上的缺陷冒充命中活跃管线。

七类纯 SR 初测与 32-SPP 参照已完成。少灯/聚光已改善；多灯、面积光、环境与混合的残余随机噪声仍然存在，不能宣称全场景已修好。下一步单独对照官方 ReSTIR DI 的无 NRD 路径，记录同场景整帧时间与参照误差，只验证候选，不暗改默认或用户 API 请求。

FG/MFG 新增交付验证在实际打包 JAR 上运行：OFF→2×→3×→4×→OFF，4× 期间来回 resize；每阶段预热后测 360 个原生帧，读取 SDK 的实际呈现计数差，不能把请求倍率当结果。沿用纯 SR，无 NRD/RR/SHaRC。质量测试中的截图读回时间不作为正常游戏 FPS。第一次启动在初始 OFF 策略返回 UNCHANGED，被新测试错误地拒绝；只修测试接纳这个正确初始状态，不将其算作 FG 运行失败。
