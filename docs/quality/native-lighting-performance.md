# Native 光照性能修复

## 最新遍历优化与干净环境对照

2026-11-04 追加两项通用优化：曼哈顿衰减先检查保守贡献上界，可能影响结果时再计算距离和方向；光源树直接访问右子节点，只将待处理的兄弟节点压栈。两项修改保持光源顺序、三种 composition、静态／动态子集及遮挡语义，不降低采样。

每轮 1,800 个新帧，1280×800、64 光源、2 GI，24 帧预热。相对本次修改前的 native，P50 4.485344→3.467360 ms（减少 22.70%），P95 5.028192→4.173984 ms（减少 16.99%）。两张完整输出逐位一致，射线与源遍历计数相同。自动频率仍会变化，这些数值是本轮观测收益。

最终跨后端对照测前 GPU 均为 0%、P8，使用相同 fixture、驱动和电源方案。旧 Vulkan P50/P95 为 3.561312/4.247680 ms，新 native 为 3.470080/4.142176 ms，分别减少 2.56%/2.48%。结论是核心光照已基本追平；不将旧端 P99 的长调度区间折算为普遍消除卡顿的收益。旧 Vulkan 仍是材质读取较简单的真实 GPU fixture adapter。

新增语料涵盖 3 种 composition × 2 种衰减 × 3 种形状 × raw/RR，并切换计数、组容量及解析灯；包含静动态独立结果、64 位 ID、零距离和范围边界。最终 432 张 raw 信号／RR 输入及 guides 与修改前逐位一致，36 次真实 RR evaluate 通过。已通过的无关测试保留，不再追加全量或 FG/MFG。

完整数据、环境、制品身份及逐帧 timestamp 见 [遍历优化数据](data/native-lighting-traversal.json)。复验语料可运行 `tools/Test-LightingBounds.ps1`；保存了基线 runtime ZIP 时传入 `-BaselineArchive` 执行逐文件对比。下文保留此前发布时的受干扰记录。

本批针对通用原生执行成本修改：候选交点先执行轻量角色／透明度判定，仅最终命中读取完整接收面；遮挡射线遇到有效不透明命中即结束；GI 入射源查询不再计算未使用的 dynamic 子集；按实际非加法组数、解析灯存在性和统计开关选择等价预编译变体。多组、任意组号和解析灯仍走完整实现。统计 OFF 的内置 raw／RR 变体不含逐射线计数代码。没有删灯、降低样本、换算法、裁覆盖或复用旧帧。

候选判定和 shadow 改动有 alpha／角色／GI 补验。raw 与 RR 各八个选择变体均已实际执行；开关计数后 raw 三个信号、RR gain／raw GI／全部 guides 逐位一致，RR 共八次成功 SDK evaluate。

## 同机受干扰对照

按用户要求保留其他 GPU 程序。同一 fixture，1280×800 光照、2560×1600 逻辑视口、64 源、2 GI、24 帧预热和每轮 600 个新帧。基线是本批 GPU 性能修改前保存的 native runtime；不是旧 Vulkan。逐射线计数、PFM 捕获在计时之外。

## CPU 局部事务

4096 mesh fixture 的灯事务 P50 523200→4300 ns，单材质事务 528000→2000 ns；Java 分配分别 1332992→2740 B、1332976→3328 B。结构共享与反向依赖索引消除了无关表复制／引用扫描。121.7×／264× 是这两个 CPU 事务的观测值，不是 GPU 或游戏提速。

## 诊断边界

DEEP 显式拆分 receiver、direct（含 sources/shadows）、GI（含 sources/shadows），采用额外接收面存储并改变调度，只用于诊断。阶段各自使用独立常量缓冲；大网格计数已与生产路径一致。source/shadow 内部仍未独立计时，不能把计数折算毫秒，也不能将诊断拆分的分位数相加来解释生产 fused kernel。

实际 GL 消费、宿主重建和游戏其他绘制由真实宿主计时。库提供 sequence／revision／generation 关联及共享发布范围；这些缺项不是零耗时。
