# Scene incremental reconciliation

The bridge retains the native scene, BLAS/TLAS builders and upload authority. Full beauty material registration stays with the original material baker; independent direct lighting does not require its GPU rows. This change transfers the prior backend's incremental principles, without transferring its backend implementation or modifying upstream rendering algorithms.

| Domain | Implemented behavior | Boundary |
| --- | --- | --- |
| Transactions | Exact-equal resources preserve persistent roots, reverse dependencies and ordered light views | Real generations, removals and validation remain effective |
| Mesh changes | Separate attributes, same-layout deformation, stable-graph geometry resize and graph topology | Mesh/group identities are preserved only when group count, material order and mesh type match |
| Acceleration | Build only changed meshes; ordinary same-layout BLAS reuse; exact-layout TLAS allocation reuse | Reshapes allocate a correctly sized BLAS; real table dimension changes use native allocation |
| Materials | Existing parameter mutations use public PTMaterial fields and GPUDataDirty; texture redirects use InitFromLoadedTexture; independent direct lighting creates public CPU PTMaterial flags | Original baker registration is required on full beauty entry, not on independent direct-lighting material insertion |
| Lighting metadata | Weak-owner identity/policy caches, geometry delta journal and owner-thread scratch | Dense native indices and true material/texture changes remain validated |
| Lifetime | Both queue fences retain displaced resources; existing reclamation fixes remain active | No early release or custom upstream capacity policy |
| Diagnostics | Actual mesh preparation and material row scopes; cumulative metadata work outside frame timing | OFF does not collect diagnostic-only snapshots |

### Why true topology previously expanded into global work

The old sparse slots did not renumber survivors. In U/External/Donut/src/engine/SceneGraph.cpp:1097-1132, a genuine structural refresh instead assigns every instance's dense index and geometry-instance prefix, every geometry's globalGeometryIndex, and every materialID. U/External/Donut/src/engine/Scene.cpp:607-710 then prepares mesh resources, updates dense rows and writes tables. Current native container reuse avoids generating a structure change for its safe matched replacements; the dense-row journal reduces repacking for remaining native remaps without replacing native index ownership.

The adapter had amplified this necessary native work: full remaps built temporary instance/mesh hash maps, inserted remapped instance names into another dirty set, looked geometry mappings up again by string, and cleared/reinserted masked identities. Current C/rtxpt_scene_delta.h:9 and native-lighting collection/upload use retained vectors, cached map-node references, direct slot staging with epoch deduplication and retained masked membership. Material policies compare both name and weak ownership. Explicit old-name retirement makes same-owner container rename safe. These changes remove adapter duplication, not the native scene itself.

### Logical range allocator equivalence: decided this round

The independently inspected RTXMU header is D:/RTXMU/include/rtxmu/Suballocator.h, not a new build dependency. The currently locked U/External/Donut/nvrhi tree does not include RTXMU source, and build/upstream-rtxpt/native/CMakeCache.txt:668 has NVRHI_WITH_RTXMU=OFF. An older build/rtxpt-sdk/External/Rtxmu header exists but differs in SHA256 from that independently inspected header; it is not treated as current locked upstream authority.

- Suballocator.h:84 constructor fixes blockSize/allocationAlignment; :105 allocate returns a block plus a within-block offset/lease, rather than one dynamically growing flat index domain.
- Its :329 findFreeSubBlock chooses exact/best-fit. At :374-404 it can reject a disproportionately large hole for a small request; accepted best-fit consumes the entire old sub-block and reports unusedSize rather than splitting the remainder into a reusable logical interval. For example, a freed 100-unit hole is rejected by a 1-unit request; a 40-unit request may consume all 100 units. AttributeRanges instead splits exactly.
- Suballocator.h:205 free records free blocks, and :258 getSize/:296 getStats expose block capacity/statistics. There is no public shrink-to-highest-live-offset, externally grow-an-existing-flat-block, or exact Release(offset,count) contract. Current end is a live logical tail, not reserved block capacity; using a fixed maximum block as end would violate real allocation growth/budget behavior.
- Merge is conditional on MERGE_FREE_BLOCKS and performed in the allocation search. Current adjacent coalescing and tail collapse happen on release. No unsupported macro changes or patched allocator are proposed.
- The template also calls Logger::isEnabled/log; Logger.h declares these and Logger.cpp defines them. It is not a completely self-contained header-only dependency.

Direct replacement would require additional block-to-flat-address mapping, lease identity and a separate live-tail index or changed allocation/budget semantics. That expands the bridge rather than delegating an equivalent existing contract. Therefore this round retains the minimal logical corner allocator, changes no allocator source/CMake, and adds no local-machine SDK path. This decision is specific to logical corner ranges; it does not weaken the requirement to use native allocators for GPU heaps, uploads or AS.

The follow-up constructs shared native BufferGroup inputs exactly as the original GltfImporter does (GltfImporter.cpp:1058-1093), within a 1 MiB/32-mesh generation. This is input construction, not a GPU allocator, custom layout, or patched uploader. Original CreateMeshBuffers/UpdateGeometry/BLAS code continues to consume native offsets. Retained authored offsets and attribute byte sizes are tracked independently so later normal/UV edits do not become geometry changes just because the previous native buffer was shared. MeshBufferUpload records actual created GPU buffers and bytes; workload summaries retain per-stage items/bytes without adding nested stages together. Original files remain unmodified under the existing two authorized UI/network exception classes.

Topology regression cases 25-27 verify two edited meshes create only one native buffer pair; then each mesh can be edited independently without changing BLAS identity, while the current normal pixels and dense metadata remain correct. Existing full-render, material lifetime, transform, deletion and deformation contracts are still required for this DLL. No application FPS target is certified by a synthetic workload.


### Native resource chain source audit — 2026-11-08

This is a source audit, not a new execution or release result. The consumer references are V3 99a345096f33b10cee840b4615d9c645885ed004 and V4 493820d445f7766e7508da0c8e03754f9e29e94e, both calling the retained-scene API 5.0.0 represented by 5c649d25c16dae8c5765ddfc01e98b2df8b8658d. The companion data/scene-incremental-native-resource-audit.json records the inspected source snapshot. No old Vulkan implementation is reintroduced into the production build by this audit.

#### Actual old execution route and idle boundary

Both old consumers use TerrainRenderer.configuration(): RendererConfig.builder(), a custom retained-scene shader, two frame slots and disabled temporal rendering. They do not select RendererConfig.recommended(). RendererConfig.Builder defaults rayTracingOptimizations to disabled, so the mere presence of renderer-nvidia and NvidiaRtxmuMemoryOptimizer in the old distribution does not establish an executed RTXMU allocation path. VulkanRendererBackendProvider.openSession actually selects VulkanGpuSceneRenderingSession.

The old route is: stable location/resource IDs and changed-only SceneTransaction → VulkanSceneResidency dirty domains → VulkanGpuSceneMemory range placement → coalesced VulkanGpuSceneUploadPlanner / VulkanGpuSceneTransferPlan → VulkanGpuSceneBuffers transfer → VulkanSceneAcceleration dirty BLAS and TLAS convergence → exact-revision frame admission → frame-slot uniforms, descriptors, fresh dispatch and exact output delivery. apply refuses mutation only while a renderer producer fence owns the scene; it does not widen that dependency to presentation or whole-queue idle.

“Uniform-only idle” needs a precise scope. With unchanged resources and instances, scene apply/upload and BLAS/TLAS rebuild are absent. A freshly traced camera frame still writes the slot uniforms, updates descriptors, records commands, traces and publishes output. GpuSceneShaderDataBuffers.update retains the same ResourceData identity per slot and skips unchanged payload writes; descriptor updates still run. The consumer also has a separate exact-input presentCached branch for a completely unchanged camera/lighting/output. That branch is historical output reuse, not the fresh-frame idle path, and is not a permitted performance substitution for this migration.

| --- | --- | --- |
| Resource placement | Per-domain VulkanRangeArena retains a live identity's sufficiently large range and releases removed/replaced ranges only through the completed descriptor epoch. GPU target buffers grow without shrinking at every live count. | Native MeshInfo/BufferGroup and graph registration remain authoritative. Shared immutable BufferGroup inputs batch changed assets through the original uploader. This removes per-mesh buffer pairs without recreating the old free-list or promising identical per-attribute byte writes. |
| Upload and staging | Adjacent target ranges coalesce into one materialized staging payload. One reusable host-visible staging buffer is recycled only after its transfer completes. | Retained native command lists preserve NVRHI's own upload and DXR scratch managers. Changed-only native mesh batches use the original uploader. The old JNI-free Vulkan submission is not byte-for-byte equivalent to the current owned JNI packet and native queue. |
| BLAS frequency | MeshDirtyMask.BLAS alone selects dirty meshes. Actual domain changes preserve the original conservative full native route. |
| BLAS batch meaning | VulkanBlasBuildCoordinator.submitBatch loops requests and submits one geometry list per request; core fallback also submits each request separately. Native NVRHI exposes per-AS build; its internal scratch allocator remains the authority. |
| BLAS backing allocation | RtGpuBuffer uses VMA AUTO_PREFER_DEVICE and WITHIN_BUDGET without requesting dedicated allocations. | BLAS replacement reuse | The reviewed old dirty-mesh route creates a new BLAS and asynchronously compacts it; it is not evidence of arbitrary variable-size BLAS destination reuse. | The new same-transaction direct candidate may reuse an actually vacated ordinary AS only for exactly equal prebuild shape, then executes a full native BUILD with current input buffers. #### Same-transaction ordinary AS reuse safety review

DirectBuildShape / SameDirectBuildShape / RefreshRetainedDirectStructures were inspected after the main-thread edit. The hash is only a candidate index; exact field comparison protects against collisions. live excludes handles still used by current instances, seen removes duplicate retired entries and erasing a selected candidate prevents assigning one AS to two new meshes. Eligible handles are ordinary, live-tracked, nonvirtual, nonpooled and uncompacted, under the non-RTXMU direct route with no OMM and no previous asynchronous prefix.

The exact key includes build flags, geometry count/order, type, geometry flags, useTransform, index format/count, vertex format/count and vertex stride. Buffer identities, input offsets and transform values are fresh full-BUILD inputs, not allocation-shape keys. All OMM attachment/index/usage fields are rejected. useTransform must remain in the key: NVRHI's prebuild query deliberately substitutes a non-null dummy transform address and warns that omitting it can under-size storage and hang the GPU.

NVRHI createAccelStruct clears the stored geometry buffer pointers. Its ordinary build uses the current supplied geometry for GPU addresses and liveness while the stored descriptor supplies the prebuild capacity/scratch shape. validation-commandlist.cpp rejects rebuilding any already-built AllowCompaction AS even when isCompacted() is false; the candidate rejects that flag as well as PerformUpdate. A full BUILD does not require AllowUpdate. The candidate records the original Write → full native BUILD → BuildBlas dependency and commits barriers. New MeshInfo and node identities retain their own previous-pose semantics. Old CPU objects and buffers continue through existing retirement.

This relies on frame-external serialized apply and native queue ordering. SceneRenderCache.Close invalidates the per-frame cache and clears its scene pointer; it must not be read or mutated as though still open. Original asynchronous prefix submissions insert a graphics wait before their frame graphics work. The conservative no-previous-async gate remains; unknown concurrent readers fall back to new allocation. This review found no source-level shape, duplicate-owner or queue-ordering defect in the candidate. It is not a compile/runtime pass. CacheHit/reason PoolHit identifies a reused allocation, not a skipped BLAS build or an actual persistent pool.

#### Official managed-resource routes and hard boundaries

The verified export locks RTXPT 303b408ab81790a5051abd7573830b7a4112eb8e, Donut e50042f4bbd762971cc90431261e967404855b81 and NVRHI 6b96fb03e07539f08327aea76c56d55f1de9d906. RTXMU is not an exported submodule in that manifest. NVRHI exposes an optional FetchContent route with the official NVIDIA-RTX/RTXMU URL and default tag v1.4. A session-proxied read of that official remote resolved v1.4 to 0c9ce1177000d5923e2cc6a35ae9cb7ff03748d2; the clean local SDK matches this exact commit/tag. A future build must explicitly lock and audit that dependency rather than trust its directory name or an old patched build copy.

| Official route | Verified support | Why it is not a blind replacement here |
| --- | --- | --- |

| Sample BlasCompactor / BlasPool | Original D3D12 load-time batching compacts static meshes into address-only pooled handles. | IsAvailable checks D3D12, with no public disable toggle. The current safe minimal route is to retain complete beauty behavior, use original native command-list upload/scratch ownership, batch supported native inputs, avoid unnecessary scene/AS work and reuse only proven same-transaction ordinary AS allocations. Global managed switching, compaction/address-table migration and placed-AS allocation are not completed work. Their hard limitations must not be hidden by a direct-only microbenchmark or by silently removing existing capabilities.
