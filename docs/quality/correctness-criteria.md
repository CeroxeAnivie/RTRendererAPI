# 通用 API 的正确性标准

2026-11-05。用户要求是功能强大、通用、结果正确的 API；没有要求所有浮点输出一律逐位相同。此前把逐位一致说成用户指定的总验收标准不准确，本页更正这一点。现有失败日志保留，不改写为通过。

## 必须准确的内容

资源 ID、帧 sequence、场景 revision、输出 generation、尺寸、编码、信号归属和生命周期必须满足契约。增删资源必须在正确的新帧生效；不能混用旧输出、漏掉遮挡、丢失贡献、重复应用颜色或越过 alpha 判断边界。无效输入拒绝、在途资源安全、慢消费者和关闭恢复都须验证。以上错误不能用浮点容差掩盖。

## 浮点结果怎么判断

先确认场景、相机、上一帧几何、历史状态、采样预算和计时范围一致，再比较结果。不能把不同输入的输出差异直接归因于优化。

| 信号 | 主要检查 |
| --- | --- |
| HDR 直接光、GI | 与解析或穷举参考比较线性能量、绝对误差、相对误差、偏差及误差像素分布；覆盖亮暗区域、极值、遮挡和源组合 |
| 运动向量 | 归一化位移换算为实际光照网格像素；检查方向、相机/物体运动、静止残差和后续 RR 的时序影响 |
| 深度 | 按声明的投影与深度约定验证，关注近远处误差及遮挡/重投影结果 |
| 法线 | 检查方向、角度与非均匀缩放，不能只比较某个分量的小数位 |
| coverage、材质边界、有效性和 identity | 判断边界与身份语义必须正确；不能用图像平均误差抵消错命中或漏命中 |
| 紧凑编码 | 使用编码自身的量化误差范围，并独立验证解码、颜色域与合成 |
| RR 输出 | 确认真实 SDK 执行；检查能量、静态稳定、移动边缘、露出区域、拖影和历史重置，不能只比较单帧 |

每项允许误差应从信号单位、存储精度、参考算法和下游影响得出，并在接受修改前记录依据。没有依据时报告未判定；不为使失败候选通过而临时调阈值，也不把“肉眼看不出”单独当作证据。

逐位一致继续作为有用的内部等价检查：例如完全相同输入下开关诊断、只改索引搜索顺序，或纯复制/搬运路径。它能帮助发现意外变化，但不是跨算法、跨设备、跨驱动的统一产品承诺。逐位失败需要调查，不自动等于产品画质失败；达到逐位一致也不能代替通用场景覆盖。

## 当前 motion 差异的解释

最大差 `1.7881393432617188e-7` 是归一化屏幕位移。对应测试实际宽度 256，约为 `0.0000458` 像素；在宽度 1280 的网格上同样数值约为 `0.0002289` 像素。这个量级本身不能证明有实际画质回归，也不能独自证明长期时序无影响。

实际 native 参数快照已确认旧对照输入不同：OFF 的 word 75 为 30，包含 previous-geometry 位 16；DEEP 为 7，不含位 16。两边投影矩阵相同。证据在 `build/reports/resource-critical-path/input-trace/native-gi-reconstruction/`。仅预热一帧未消除这一状态差异；限制投影运算重排的尝试也无效，已撤回。后续通过明确核对输入，以及复现相同相机/物体运动轨迹来检查诊断等价，未增加输出容差。

## 与性能验收的关系

完整请求 GPU P95 ≤4 ms 仍是性能目标。正确性与性能分别报告；不降低分辨率、采样、GI/RR 质量或通用 API 能力来换取达标，也不缩短计时边界。性能收益必须提供旧值、新值、绝对差、百分比、相同条件与证据。失败候选继续撤回并留记录。
