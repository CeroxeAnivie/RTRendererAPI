# 玻璃输运修复与验收，2026-11-02

本轮修复位于 RTXPT 的共用玻璃输运逻辑，不按 Demo 名称、实例 ID、屏幕坐标或灯的位置改变渲染。4×4 像素范围仅用于诊断采样；关闭诊断后这段采样代码不进入着色器。

## 已确认的原因和修改

1. 直线透明阴影查询将出口角度当成真实内部折射角，错误触发全反射。`RtrLegacyDirect.hlsli` 对直线可见性使用互易外部角度近似；实际折射射线仍保留真实全反射。参考 NVIDIA RTX Remix 的 `algorithm/visibility.slangh`。此可见性近似不等同于完整焦散积分。
2. 第一界面之后按固定像素随机数选择反射或透射，在高对比彩灯旁产生明显空间颗粒。公共路径现对前六个表面顶点内的玻璃界面按 Fresnel 权重枚举两支，未访问的后缀跳过，共享前缀直接光和自发光只累计一次。参考 PBRT Whitted 的反射、透射求和。第七顶点及以后仍使用原抽样估计，不能把此修复称为任意深度的零噪声保证。
3. RTXPT 原生 BSDF 将粗糙度小于 0.04 的玻璃识别为 delta 界面；移植的实际输运仍扰动该界面的微法线。现与 pinned RTXPT `BxDF.hlsli` 的 `kMinGGXAlpha`、`EnableDeltaBSDF` 及等折射率规则对齐。材质参数和 SR 输入分辨率不变。
4. 构建脚本在重复配置时重新插入已被替换的旧循环，引起着色器括号不匹配。已修复迁移幂等性；连续两次配置生成相同的 raygen SHA256，FILL 着色器独立编译通过。

## 使用范围及性能验收

上述渲染候选仍由 `RTR_RTXPT_DIAGNOSTIC_LEGACY_LIGHTING=1` 启用；这是选择渲染逻辑的历史命名，并不代表必须启用日志。默认上游路径以及 ReSTIR/SHaRC 路径没有自动启用这组候选。本轮不宣称所有后端/高级能力已经完成无噪声回归。

性能运行前执行 `tools/Build-RtxptOpticalTrace.ps1` 关闭 GPU 路径日志、恢复随机种子和粗糙度控制；不启用 GPU stage profile，关闭 API GPU 计时，保留同一组已验收的渲染逻辑。计时脚本检查 trace 制品、初始 GPU 0 占用及运行输出，避免误测诊断版本。FG 关闭时统计原生帧，FG 开启时分列原生与实际呈现帧率。
