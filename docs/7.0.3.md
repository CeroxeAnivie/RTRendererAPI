# RTRendererAPI 7.0.3

7.0.3 修复 retained scene 中单灯更新、材质同步和 pipeline 重建的全量开销，新增连续照明策略、独立主视线背景与执行诊断。四个模块统一使用 7.0.3，Java 25 基线不变。公开 API 只增加 `SceneLightingControl`，保留 7.0.0／7.0.2 的已有二进制声明。

`SceneTransaction` 的 revision 仍表示 CPU 接受的场景版本；`submit` 才应用原生资源并渲染对应相机。普通更新保持同步，不用旧帧冒充新帧。CPU 校验失败保留原 revision；原生提交失败关闭会话，避免呈现部分更新。关闭仍排空 GPU 并退休资源。

- 相同 ID／类型的灯只传变化记录，更新原生对象和灯树祖先包围盒、功率与范围；GPU 只上传变化的记录和树节点。所有灯仍有采样支持，不做最近 N 灯截断。灯的增删和类型改变仍使用完整灯代际提交、重建树。
- 按不可变 mesh 身份缓存材质依赖，纹理／照明更新不再扫描未变网格的每个三角形。材质成员判断改为哈希集合。材质变体的实际 shader key 未变时保留变体对象；仅实例／几何映射改变且 shader exports 相同时只重建 SBT，保留 pipeline。
- 相同纹理身份、尺寸、寻址和 alpha 通道的颜色动画保留 alpha coverage／OMM／BLAS。alpha 通道、尺寸、寻址、透明域或 cutoff 改变仍保守重建相关结构。普通资源更新仍有 fence 等待，并非无等待异步上传。

可查询的通用控制：

```java
var control = renderer.extension(SceneLightingControl.class).orElseThrow();
control.lightingContinuity(SceneLightingControl.Continuity.CONTINUOUS);
control.visibleBackground(0.05f, 0.1f, 0.2f); // 线性场景辐亮度，之后正常曝光／tone mapping
```

`supportsContinuousLighting()` 查询当前配置是否支持连续策略。默认 `DISCONTINUOUS` 保留旧行为。`CONTINUOUS` 支持 `SCENE_ANALYTIC`、关闭 ReSTIR 与辐射缓存的路径，包括 RR、SR＋NRD、无重建；不支持的组合明确抛出异常。每帧仍使用并上传真实输入，推进随机样本。连续变化不清空 RR／SR／NRD 历史，路径积累仍失效；灯拓扑变化或超过阈值的突变自动清理重建历史。阈值逐次比较：能量／范围约 10%，方向点积 0.995，位置约 range 的 5%（下限 0.02 世界单位），锥角余弦 0.05；零／近零能量有 0.001 的绝对阈值。连续性是应用提示，不是长期冻结历史或忽略小输入。`RenderFrameRequest.resetTemporalHistory(...)` 现执行原生重置，可用于相机切换和显式不连续事件。

`visibleBackground` 仅替换没有命中表面的主射线，反射、折射和间接照明继续读取环境。`environmentBackground()` 恢复默认。自动曝光、bloom 等屏幕效果仍能对整幅画面作出响应；比较物体照明时应固定这些显示策略。原生呈现和 D3D12 GPU 共享帧均使用相同的 opaque SDR 输出，无常规 CPU readback。

本版不提供透明 coverage 输出：`supportsTransparentBackground()` 返回 false。不能据此把宿主已有天空保留下来；消费方也不能用 overwrite blit 代替 alpha 合成。透明主背景需要另行完成重建边缘、coverage 和共享帧的合成合同，本版不将 miss 简单清零冒充支持。

`RtxptAccess.submitStages()` 提供累计校验、翻译／文件、native importer、纹理 finalize、材质、AS、pipeline、退休时间及灯 delta／refit、pipeline／SBT 计数。Java inclusive scope 与 native 子阶段有包含关系，不能相加。`retainedUpdateTimings()` 继续分开报告 fence CPU 等待与 GPU queue interval；后者不等于 GPU busy time。`historyFrame()` 把本次提交的环境、单灯、资源、相机、背景和输出尺寸等输入变化与实际分作用域的动作对应到帧序列。`historyActions()` 在路径积累、SR／RR、NRD 的实际调用位置计数；缓存项是已执行的失效通知，不冒充 GPU cache clear。旧 `lightingTimings().historyInvalidations()` 仍是照明引发的重置请求数。

验证、量化收益、失败记录及实际制品 hash 见 [7.0.3 验收](quality/rtxpt-retained-703.md)。源码推送 GitHub 后，四个模块发布 Maven Local；不发布 Central。
