# RTRendererAPI 7.0.0

7.0.0 重新定义介质 API 与 GPU 执行结构。这是破坏性主版本：应用、API、core、NVIDIA provider 和自定义场景 shader 必须一起迁移，不提供 6.x 介质包装类或旧执行链。

介质数据使用不可变 record，直接表达吸收、散射、发光、密度、折射率和相函数参数。环境、持久实例、逐帧图元和质量策略使用同一组类型：

```java
var water = new Medium(
    new Rgb(.02f, .01f, .005f),
    new Rgb(.04f, .04f, .04f),
    Rgb.ZERO,
    1f, 1.333f, .2f
);
var boundary = MediumBoundary.surface(water).withPriority(2);
var quality = new MediumTransport(12, 1, 8, 4, 512f, 1e-4f);

var instance = SceneInstance.builder(2, 2)
    .mediumBoundary(boundary)
    .build();
var environment = EnvironmentState.builder()
    .cameraMedium(Medium.vacuum())
    .build();
var frame = RenderFrameRequest.builder(sequence, width, height, camera)
    .environment(environment)
    .mediumTransport(quality)
    .build();
```

`MediumBoundary.volume(medium)` 声明不可见的纯体积边界；`surface(medium)` 保留表面材质交互。边界要求封闭、绕序一致的流形网格。重叠区域由优先级选择介质，退出后恢复外部介质。`Medium.vacuum()` 是唯一真空入口。

## 从 6.x 迁移

| 6.x 接口 | 7.0.0 接口 |
| --- | --- |
| `EnvironmentState.Medium` 与其 Builder | 顶层 `Medium` record 与 `Rgb` record |
| `MediumBoundaryState` 与其 Builder | `MediumBoundary` record |
| `MediumTransportOptions` 与其 Builder | `MediumTransport` record |
| `phaseAnisotropy()` | `Medium.anisotropy()` |
| 独立通道的消光、散射和发光 getter | `absorption()`、`scattering()`、`emission()` 与 `extinction()` |
| `maxInterfaceEvents()`、`maximumDistance()` | `maxEvents()`、`maxDistance()` |

7.0.0 不会识别旧类名或旧构造参数并自动转换。历史 6.x ABI 文件与报告保留为版本记录，不参与新介质实现的运行。

## 执行结构

普通模式通过 `Renderer` 提交 retained scene 和 `MediumTransport` 预算。后端根据本帧实际场景事实，在 surface、小容量介质和通用介质程序之间自动选择；调用方无需选择内部 shader 变体。

专家模式使用显式资源/命令事务，或通过 `SceneShaderProgram` 替换 retained-scene 阶段。自定义阶段不会被 surface 优化覆盖，也不会由普通模式的介质策略改写。应用缓冲区绑定、资源代际、同步和生命周期仍遵守各自的显式契约；任意 SBT、递归或程序化几何使用 command path。两层入口共用 `Renderer`，不增加兼容性的 `expertBuilder` 入口。

场景分类只使用实际实例引用的网格与材质，未使用的玻璃材质和未实例化的网格不会使普通场景进入介质路径。帧内图元同样参与分类，资源变更后重新计算相关事实。

均质吸收和发光在射线段内直接解析积分。散射与可透射阴影通过独立的轻量查询阶段访问场景，不再使用携带完整表面状态和介质路径的嵌套 miss 服务。纯体积边界在命中阶段尽早返回，避免执行不需要的表面纹理与 PBR 工作。

内置程序区分已证明的不透明真空场景、小容量介质路径和通用介质路径。小容量选择依赖保守的边界数量证明，不会只依据相机当前所在深度缩小容量；位于屏幕外的边界也可能被反射或光源射线访问。

## 质量与预算

`MediumTransport.balanced()` 使用 12 个界面事件、1 个光学样本、8 个散射区间、4 个灯光样本、512 的积分距离和 `1e-4` 的透射率截断阈值。额外体积散射次数默认为 0。

| 参数 | 取值 | 含义 |
| --- | --- | --- |
| `maxEvents` | 1–32 | 每条光学路径的界面/表面事件预算，包含主命中 |
| `opticalSamples` | 1–8 | 每个主射线样本的首个光学界面采样预算 |
| `scatteringSteps` | 1–64 | 射线段内散射积分与非均匀密度积分分辨率 |
| `lightSamples` | 0–8 | 体积灯光采样预算；0 枚举全部灯光 |
| `maxDistance` | 有限值，`(0, 1_000_000]` | 从主射线开始累积的介质积分距离；不缩短真实遮挡射线 |
| `transmittanceCutoff` | `[0, 1)` | 低透射率截断策略；0 关闭该近似 |
| `scatteringBounces` | 0–8 | 首次散射之后允许的额外体积散射事件；0 关闭额外路径 |

增加步数主要改善沿射线变化的灯光与阴影积分；增加灯光样本主要减少多灯采样噪声。二者不相互替代。`lightSamples=0`、`transmittanceCutoff=0` 可用于生成更严格的对照结果。界面事件与距离预算仍然存在，需要按场景尺度和嵌套复杂度选择。

首个光学界面分开追踪反射与透射；后续界面通过概率选择一条续接路径。粗糙界面使用各向同性 GGX 可见法线采样和匹配的遮蔽/PDF 权重，透射包含辐亮度的折射率平方比例。透明覆盖孔直接穿过，不能当作有色玻璃。边界几何半球不合法的微表面样本贡献为零，不改写介质状态。

事件预算耗尽后，光学路径只保留已积累的辐亮度，不凭空补天空；阴影路径返回保守遮挡。`maxEvents=1` 因而不再访问主命中之后的几何。积分距离耗尽只停止后续体积积分，几何可见性仍继续遵守事件预算。

## 密度网格与多次散射

`Medium` 的完整构造参数追加 `MediumDensityField densityField`。六参数构造使用 `uniform()`，密度因子处处为 1；`withDensityField(...)` 可指定网格：

```java
var field = MediumDensityField.grid(textureId, 16,
    new AffineTransform(new float[]{.5f,0,0,.5f, 0,.5f,0,.5f, 0,0,.5f,.5f}));
var fog = water.withDensityField(field);
var multipleScattering = MediumTransport.balanced().withScatteringBounces(2);
```

密度资产必须是 LINEAR RGBA8。基础 mip 的红通道除以 255 得到空间乘子，其他通道忽略；尺寸为 `W × (H*slices)` 的竖直切片图集表示 `W × H × slices` 网格，Z 切片沿图集 Y 递增。UVW 立方体外密度为零，内部使用以体素中心为基准的三线性插值，在域边缘钳制体素。普通纹理的寻址、滤波和 mip 策略不改变密度采样。

边界介质的变换将对象局部坐标映射到 UVW；环境介质的变换将世界坐标映射到 UVW。空间乘子与 `Medium.density` 相乘，同时缩放吸收、散射和发光，折射率与各向异性保持不变。非均匀密度使用有界中点区间近似；它不是任意精度的解析密度积分。

`scatteringBounces>0` 在首次散射积分点采样 HG 方向，继续追踪实际的额外体积碰撞、边界、表面和灯光。RGB 自由程按三个消光通道混合采样，并对碰撞与逃逸分别补偿概率。达到额外次数后只保留无后续散射的传播项；这是有限阶多次散射，不保证高密度介质的收敛。

默认 0 使用单次散射与平坦环境照明近似；正值改用方向采样和带遮挡、衰减的天空/表面入射辐射，因此从 0 到 1 也会改变首次散射的环境照明模型。它不只是为同一结果添加第二阶。透明阴影沿直线估计透射；需要表面聚焦光纹时，显式开启下述光子焦散。光谱色散与任意相函数仍不在内置范围。

密度网格或额外散射需要专门的扩展体积程序，按场景事实和帧预算自动选择。没有生效网格且额外次数为 0 时，保留均质程序；未引用资产不会开启扩展路径，纯不透明场景保留 surface 程序。增加次数会为每个首次散射积分点增加几何追踪、自由程积分和灯光可见性查询；密度网格又会放大每次积分成本，不能承诺固定提速或固定帧率。

## 表面焦散

`RenderFrameRequest.caustics(Caustics)` 独立控制反射、折射后的表面光子图。默认关闭，不分配光子图、不派发光子阶段。示例：

```java
var caustics = Caustics.photonMap(0, 2, 0, 12f, 131_072, .16f)
    .withMaxEvents(20);
var frame = RenderFrameRequest.builder(sequence, width, height, camera)
    .mediumTransport(MediumTransport.balanced().withScatteringBounces(2))
    .caustics(caustics)
    .build();
```

世界空间发射球必须严格包围全部显式介质边界的世界包围盒，球内漫反射表面接收焦散。太阳、方向灯、点灯和聚光灯采用匹配发射 PDF 的光通量权重，光子通过至少一次反射或不同折射率的界面后，在首个漫反射接收点存储。均质、异质介质均对光子做消光；体积焦散密度不在这个表面估计器的范围中。

查询使用固定半径、归一化表面核和空间哈希；存在半径引入的偏差和有限光子数噪声。法线及实例身份限制跨表面漏光。启用后增加独立追踪、哈希查询和每个帧槽的缓冲区成本；提高光子数量和减小半径需要一起评估。漫反射直射估计在受支持区域阻断穿过折射界面的直线项，避免与光子焦散重复；表面高光与体积直射仍保留已有直线透射近似。

该内置策略要求 `SceneShaderProgram.builtIn()`；专家自定义场景程序开启它会收到 `INVALID_CAUSTICS`，显式 command path 继续由应用决定算法与资源。内置光子绑定为 33，应用只读数据绑定从 `SceneShaderBindings.APPLICATION_DATA = 34` 开始；自定义着色器也必须迁移。

## 介质展厅 demo

新增 [介质展厅](medium-gallery.md)，默认原生 **2560×1440、1 spp、请求 2× FG**，一个场景同时放置嵌套玻璃/水体、彩色吸收、异质雾、多次散射、发光体积和焦散接收地面。命令行支持功能消融、内外相机、正反绕序、持久/帧内边界与无 FG 截图。

本次编译提交包含该 demo 和 GPU 测试入口；上传之后进行正式启动与图像/性能验收，结果另行记录。FG 是否实际生效以运行时证据为准。

## 验证范围

本轮按要求仅以构建、离线 shader 编译和不打开 GPU 设备的 CPU 检查验收；实际执行结果以统一构建记录为准。CPU 参考覆盖光学积分、Fresnel/Snell/全反射、GGX 权重、HG 归一化与逆采样、RGB 自由程概率、有限散射阶的已知解，以及非均匀密度积分和图集插值。CPU 参考不代替 shader 运行结果。

7.0.0 的 GPU 帧率、驱动执行行为和图像质量尚不在本轮验收结论中。6.0.4 的实测结果不能替代新实现的结果。专项场景代码保留，允许在后续批准 GPU 验证后复用。

实现依据、验收方法与性能限制见 [介质设计与质量说明](quality/7.0.0-medium-design.md)。
