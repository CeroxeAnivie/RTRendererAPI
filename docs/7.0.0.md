# RTRendererAPI 7.0.0

7.0.0 为破坏性版本。普通 Vulkan 渲染、弹球及通用资源/命令接口继续走 `vulkan-rt` 后端；透明介质改用可选的 `rtxpt` 后端，由 NVIDIA RTXPT v1.9.0 执行。删除旧 LuxCore 及自维护 CUDA 介质传输链，不保留兼容回退。

## 接入

普通应用依赖 `top.ceroxe.rt:renderer-api:7.0.0`。需要托管介质时，再添加 `top.ceroxe.rt:renderer-rtxpt:7.0.0`：

```java
try (var renderer = Renderer.open("rtxpt",
        RendererConfig.pathTracedPresentation())) {
    var host = renderer.extension(RtxptAccess.class).orElseThrow();
    renderer.apply(scene);
    renderer.submit(frame);
    while (host.renderFrame()) { /* 宿主事件循环 */ }
}
```

`Renderer` 来自 `top.ceroxe.rt.renderer.api`，`RtxptAccess` 来自 `top.ceroxe.rt.renderer.rtxpt`。所有调用在创建线程执行；一个进程同时只有一个 RTXPT session。常驻 JNI host 控制窗口生命周期，画面在 GPU 上直接 Present。普通帧循环不启动 EXE、不截图、不经 CPU 搬运整帧。

## 介质合同

```java
var medium = new Medium(new Rgb(.02f, .01f, .005f), 1.5f);
var boundary = MediumBoundary.surface(medium).withPriority(4);
```

`Medium` 只有 RGB 吸收系数和 IOR。系数按场景长度单位取倒数，经 Beer 关系映射到上游 attenuation color/distance。`MediumBoundary` 只有介质和嵌套优先级，要求有表面交互、封闭且绕序一致的网格。优先级采用上游约束，越界直接拒绝。

| 能力 | 当前范围 |
|---|---|
| 均匀吸收、Fresnel、折射、全反射、粗糙透射 | RTXPT 原生材质与路径追踪 |
| 封闭嵌套介电材质 | 上游嵌套优先级和介质栈 |
| 混合表面 | 同一 RTXPT 场景内处理可表达的 PBR、金属、表面发光、纹理和灯光 |
| DLSS / DLSS-RR、NRD、SHaRC、ReSTIR DI/GI、SER、Reflex | 由 Java 配置传入 RTXPT；以 `runtimeStatus()` 和 `RenderingFeatureCapabilities` 的运行时回读为准 |
| DLSS Frame Generation / Multi Frame Generation | `FrameGenerationOptions` 固定倍率 2x/3x/4x；上游查询到的倍率上限会拦截不支持的请求并保留原生帧呈现 |
| 原生上游场景 | `loadNativeScene(Path)`；与 Java retained 场景二选一 |
| 窗口、相机、变换、尺寸、显式捕获 | 薄 JNI 控制；静态资产只在结构变化时导出 |
| 通用 Vulkan 命令、自定义 shader、屏幕叠层 | 仍属普通 Vulkan 后端；RTXPT 拒绝无法表达的输入 |

DLSS-RR 包含重建降噪，启用时上游不叠加 standalone NRD。ReSTIR 与重建模式的实际组合受上游规则约束。`RendererConfig.pathTracedPresentation()` 默认关闭 FG；游戏可显式开 2x/3x/4x。RTXPT 样例不提供带倍率上限的 adaptive MFG 控件，因此 preferred adaptive 请求回退为原生呈现，required 请求会被拒绝。FG 会在场景载入和窗口缩放期间暂停，待尺寸及场景处理后恢复。Streamline 手动挂钩先升级 DXGI factory，由代理拦截 swapchain 创建，使公共 present 清理路径每帧运行。`RenderingFeatureCapabilities` 在原生 session 建立后提供能力快照，`RendererFeatureController.effectiveProfile()` 回报实际协商结果。OMM 等上游内部机制不另设无效开关；“上游包含代码”不等于适配层已验收全部组合。

## 删除的功能与参数

撤下体积单次/多次散射、HG 各向异性、异质/程序密度、体积自发光、无限介质、相机初始介质、不可见体积边界和旧光子图介质算法。对应 `scattering`、`emission`、`density`、`anisotropy`、`MediumDensityField`、`MediumTransport`、`cameraMedium` 及旧积分预算入口已删除。表面发光不等于体积自发光。

混合场景必须将互相反射、折射和遮挡的物体交给同一 RTXPT 场景，不能拼接两张独立图冒充正确的混合光传输。普通 Vulkan 自定义场景能力不等于 RTXPT 能接受任意自定义着色。

## 原生运行时

目标为 Windows x86_64、Java 25、兼容 D3D12/DXR 的 NVIDIA RTX 和驱动。RTXPT JAR 内含固定版本 JNI、签名 Streamline/DLSS DLL、D3D12 Agility SDK、shader 和原始第三方许可证。运行时流式校验 SHA-256，一次解包至用户缓存，之后复用，无需消费者安装 CUDA 或手工复制 SDK。

`top.ceroxe.rt.rtxpt.runtime` 可显式指定原生目录，`top.ceroxe.rt.rtxpt.cache` 可改缓存根目录。源码运行可使用构建目录；发行包不依赖开发机绝对路径。编译与加载只写宿主日志，不创建独立进度窗。首次 shader/PSO 准备不计入稳态 FPS。

项目适配代码采用 Apache-2.0；NVIDIA 和其他运行时保留各自许可证。见 `renderer-rtxpt/NOTICE-RTXPT.txt` 及 runtime 中的 `ThirdPartyLicenses/`。

## 构建与验收

```powershell
./tools/Build-RtxptBridge.ps1 -StreamlineSdk '<Streamline SDK目录>' -MemoryLimitGB 7
./gradlew.bat :renderer-rtxpt:check :renderer-rtxpt:rtxptNativeSelfTest
./gradlew.bat :demos:hex-ball:rtxptMediumBenchmark
```

性能计真实 Present，预热后计时，计时边界等待 GPU 完成。1080p 指输出分辨率。推荐路径为 1 SPP、DLSS-RR Balanced、SHaRC、SER、Reflex，FG 关闭；实际内部尺寸和回退一起报告。原生 1080p/1 SPP 另测。

实施证据见 [RTXPT 记录](quality/rtxpt-managed-medium-migration.md)。旧 CUDA/LuxCore 性能、54 场景及 HDR 检查属于历史实现，不是新后端的验收证据。
