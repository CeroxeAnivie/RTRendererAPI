# RTRendererAPI 7.0.0

7.0.0 使用不可变介质类型与统一 `Renderer` 入口。介质数据、预算、场景更新与帧提交共用一套公共 API；后端按介质和材质组合选择原生路径。旧 GLSL 介质执行器已移除。下表列出当前实现范围和被明确拒绝的组合。

## 公共入口与分层

应用仅依赖 `top.ceroxe.rt:renderer-api:7.0.0`。公开 API 包含环境、持久场景、逐帧图元、介质、帧预算、资源/命令事务、输出与生命周期契约；core 实现 Vulkan 场景、追踪和 CUDA 介质调度；NVIDIA provider 提供独立的厂商功能实现。公共调用方无需选择内部 shader、manager 或 ABI。

普通场景通过 `Renderer.apply(SceneTransaction)` 与 `submit/trySubmit(RenderFrameRequest)` 进入；专家工作通过同一 `Renderer` 的显式资源/命令接口进入。应用自定义 retained-scene shader 自行负责传输，不套用内置 CUDA 介质的准入条件，也不会自动插入内置介质执行器。仅通过 `SceneShaderProgram.builder().dataBindingCount(n)` 声明应用缓冲区、没有替换 shader 阶段时，仍使用完整内置介质传输；每帧须提供恰好 `n` 个正长度、四字节对齐且符合设备大小限制的 `shaderData`。数据布局不会关闭介质执行，也不会赋予内置 shader 额外的应用数据语义。未声明 binding、数量或大小错误统一以 `INVALID_SHADER_DATA` 拒绝。

新建 renderer 后直接提交帧，会先正式接纳空场景 revision 0。之后的显式场景事务必须从更高版本开始；若应用先 `apply`，则仍可从 revision 0 开始。背压不推进帧序列，已接纳的场景代际在设备恢复后重放。

## 介质数据契约

```java
var absorption = new Medium(
    new Rgb(.02f, .01f, .005f), Rgb.ZERO, Rgb.ZERO,
    1f, 1f, 0f);
var environment = EnvironmentState.builder().cameraMedium(absorption).build();
var frame = RenderFrameRequest.builder(sequence, width, height, camera)
    .environment(environment)
    .mediumTransport(MediumTransport.balanced())
    .build();
```

`Medium` 表达吸收、散射、发光、密度、折射率、各向异性与可选 `MediumDensityField`。六参数构造采用均匀密度。环境、持久实例和逐帧图元共用这些类型。

`MediumBoundary.volume(medium)` 表示不可见体积边界；`surface(medium)` 保留表面交互。边界要求封闭、绕序一致的流形几何。重叠区域按优先级选择介质，退出后恢复外部介质。`Medium.vacuum()` 表示真空。数据能够表达的组合，不等于当前后端已经实现该组合。

## 当前原生实现范围

| 能力 | 实现范围 | 输入要求 |
| --- | --- | --- |
| 吸收与发光 | RGB 透射率、发光积分、命中/未命中、累计距离预算 | 均匀介质或密度图集 |
| 单次与多次散射 | HG 相函数、RGB 混合自由程、灯光采样、实际遮挡与光路衰减 | 额外散射次数 0–8，密度积分区间 1–64 |
| 介质边界 | 内部相机、持久/逐帧边界、进入/退出、嵌套与重叠优先级 | 封闭一致绕序网格，最多 32 层；改变折射率时开启表面交互 |
| 玻璃与部分透射 | 平滑/粗糙折射、Fresnel、全反射、首界面分裂/随机单分支；部分透射保留表面光照和介电延续的各自权重 | 单面/双面遵守公共背面规则；有表面交互的封闭边界维护介质栈 |
| PBR 接收面 | PBR 直接光、介质相机路径和灯光连接；密度及显式边界使用同一 CUDA 传输 | 单面或双面；UNLIT 终端使用其颜色与发光 |
| 金属反射 | 与普通表面路径相同的一次 GGX 金属反射，反射前后均积分吸收、发光、密度与散射，保留当前介质栈 | 单面或双面、完整覆盖的不透明 PBR |
| 覆盖与表面合成 | 材质、顶点、纹理 alpha；背景延续；接收 mask/深度判定；ALPHA_OVER 与 MULTIPLY 叠层 | 无竞争延续分支时精确合成；覆盖孔洞与金属/介电分支竞争时使用概率补偿采样 |
| LIGHTMAP_MODULATED | 保留贴图、顶点色、帧 lightmap、距离雾与 surfaceVisibility 的现有合成语义，再执行介质积分 | 分数覆盖继续追踪背景；不额外添加 PBR 光照 |
| 表面与体积焦散 | 有界光子图、均匀/密度介质、显式边界、粗糙玻璃、金属及非金属 PBR 反射、嵌套 IOR、内部光源；相机按当前介质读取体积记录 | 发射球包围显式介质边界；完整光子记录受驻留预算约束 |

`:renderer-core:cudaOpticalMediumProductionNativeSelfTest -PopticalVolumeCaustics` 已通过 16 帧生产检查，包含 PBR 相机/灯光双段 Beer 对照和 12 帧体积焦散组合。PBR 最大绝对误差为 `6.185226823642032E-5`；零密度与真空相同。完整集成结果在[验收清单](quality/verification-report.md#api-closure-20261030)记录。

`:renderer-core:cudaMetallicMediumProductionNativeSelfTest` 通过 40 项最终 HDR 检查，其中 25 帧执行原生光学传输，覆盖金属率 0.2/1、单/双面、SPP 1/2/8、反射前后介质段、持久/逐帧边界和焦散开关。非金属 PBR 的显式边界及全局密度焦散也有实际亮度对照。

`:renderer-core:cudaCompositeMediumProductionNativeSelfTest` 通过 29 项解析或两端混合对照、37 帧原生光学输出，包含三种 alpha 来源及乘积、密度/边界、逐帧图元、LIGHTMAP/分数 visibility、两种叠层与 mask/深度判定、PBR 部分透射光连接及 Snell/Fresnel/Beer。该组最大绝对误差为 `4.87772653e-4`。这些新表面能力与散射、焦散的进一步交叉专项、完整集成、展厅和最终制品验收继续推进。

内置介质执行器与应用自定义 retained-scene shader 使用各自明确的执行合同。声明应用数据 binding 与替换 shader 阶段分别判断；只有实际替换阶段才由自定义 shader 负责传输。应用通过统一 `Renderer` 入口选择场景或专家工作，不需要操作内部 manager。

随包提供适用的第三方许可证、NOTICE 与来源清单；源码完整性检查会核对清单中的文件、字节长度和 SHA-256。第三方声明仅记录实际纳入的代码与适配范围，不表示纳入完整第三方渲染器。

## 质量与预算

| 参数 | 取值 | 含义 |
| --- | --- | --- |
| `maxEvents` | 1–32 | 光学界面/表面事件预算 |
| `opticalSamples` | 1–8 | 每个主样本的光学采样预算 |
| `scatteringSteps` | 1–64 | 段积分/密度中点区间数 |
| `lightSamples` | 0–8 | 每区间灯光预算；0 枚举全部灯光 |
| `maxDistance` | `(0, 1_000_000]` | 从主射线开始累积的介质积分距离，不缩短真实遮挡查询 |
| `transmittanceCutoff` | `[0, 1)` | 低透射率截断；0 关闭 |
| `scatteringBounces` | 0–8 | 直接单散射之外的额外体积碰撞次数 |
| `firstInterfaceSampling` | 确定性分裂/随机单分支 | 首界面的反射/折射采样策略 |

`balanced()` 为 12 个事件、1 个光学样本、8 个区间、4 个灯光样本、512 积分距离、`1e-4` 截断与 0 次额外散射。`realtime()` 显式降低区间和灯光预算；它改变误差和方差，不能用它替代同质量性能对照。

多散射是有限阶估计，不保证高密度收敛。0 次与正次数使用不同的环境照明估计：0 次使用平坦环境近似，正次数采样实际方向上的天空/终端辐射。事件耗尽不凭空补天空，距离耗尽只停止体积积分。粗糙玻璃、密度和显式介质边界可在同一光学传输路径中组合。

## 密度资产

`MediumDensityField.grid(textureId, slices, transform)` 使用 LINEAR RGBA8 纹理的基础 mip 红通道。`W × (H*slices)` 图集表示 `W × H × slices` 网格，Z 沿图集 Y 增长。域外密度为零，域内以体素中心做三线性插值并在域边缘钳制。材质纹理的寻址、滤波和 mip 设置不改变密度采样。

边界介质的矩阵从对象局部坐标映射至 UVW，环境介质从世界坐标映射至 UVW。空间密度乘上 `Medium.density`，共同缩放吸收、散射和发光。区间中点近似受 `scatteringSteps` 控制。

## 部署、测试和性能

当前发行目标为 Windows x86_64、Java 25、Vulkan RT 与 NVIDIA CUDA GPU。NVRTC 编译器、匹配 builtins 及许可证嵌入 core JAR，运行时校验后从 classpath 自动加载；无需消费者配置本机 build 路径。参见 [制品说明](runtime-distribution.md)。

`check` 验证公开 ABI、模块边界、CPU 合同、shader 源码/SPIR-V 一致性、第三方源码清单与供应链清单。`:renderer-core:rendererCoreMediumNativeGate` 在真实硬件验证介质路径的最终 HDR 与资源生命周期。`:renderer-core:rendererCoreUnifiedApiNativeGate` 验证统一入口的自定义场景、资源/命令、光追与帧互操作契约。代码接入不代表门禁已通过；发布候选必须同时通过这些检查和打包消费者 smoke。

性能使用固定制品、相同预算、完整 CPU HDR 交付和 ABBA 对照；结果只适用于被测场景。当前候选的实机记录见 [制品验收记录](quality/verification-report.md#7-0-0-package-validation-20261029)。[介质展厅](medium-gallery.md)提供按能力切换的验收场景和 FPS 窗口。
