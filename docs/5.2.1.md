# RTRendererAPI 5.2.1

5.2.1 is the GitHub-only maintenance release for the 5.2 retained-scene and medium transport
contract. It is not uploaded to Maven Central; Central remains at 5.1.0. The three runtime modules
must be consumed at the same version from the local repository or the GitHub source build.

The public API remains compatible with the 5.x ABI. This release keeps the complete 32-level
medium path, homogeneous absorption, emission and single scattering, Snell refraction, Fresnel,
total internal reflection, nested boundaries, frame-local boundaries and runtime quality controls.
`MediumTransportOptions.balanced()` remains the default: 12 interface events, 1 optical sample,
8 scattering intervals and a 512-unit integration budget. The distance budget limits optical
integration; it never shortens the real geometric ray used to find a receiver or blocker.

The generic CPU topology admission path now uses compact edge pairing and vertex-star checks. It
welds exact coincident seam positions, rejects open or inconsistently wound surfaces, rejects
non-manifold edges and pinched vertex links, and caches the immutable result. On the recorded
49,152-triangle fixture, admission allocation fell from 46,823,584 bytes to 8,943,632 bytes.

GPUScene medium paths avoid dynamic local-array indexing and reuse a shared lighting/transport
implementation. Custom retained-scene pipelines inspect their compiled SPIR-V before creation;
an internal shadow-service miss is omitted only when all stages are proven to use miss record zero
and no nested trace. Dynamic miss indices, nested traces and actual medium-service calls retain the
full depth-two pipeline and SBT layout. This is a generic provider optimization and requires no
consumer compatibility layer.

Validation completed for this release includes API checks, topology checks, SPIR-V compilation,
all 34 pinned shader variants, and the pipeline-requirement contract. Native GPU and interactive
FG/MFG acceptance remain separate hardware checks; a successful pipeline creation or a first frame
does not constitute visual acceptance. Minecraft visual correctness is tracked independently and
is not a release gate for this API artifact.

The release is intended to be consumed locally with `5.2.1`. No Maven Central publication task is
part of the release procedure.
