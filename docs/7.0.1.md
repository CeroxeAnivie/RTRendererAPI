# RTRendererAPI 7.0.1

7.0.1 修复原生 RTXPT 内存浪费，并完整引入通用环境／灯光增量更新，延续 [7.0.0 的 API、介质和平台合同](7.0.0.md)，不改变路径质量预算；renderer-api 核心 API 合同与 ABI 保持不变，可选的 RTXPT 后端扩展兼容新增诊断入口。

当前依赖为 `top.ceroxe.rt:renderer-api:7.0.1` 和可选的 `top.ceroxe.rt:renderer-rtxpt:7.0.1`。Demo 文件名同步为 `RTRendererAPI-HexBallDemo-7.0.1.jar`、`RTRendererAPI-MediumDemo-7.0.1.jar`。

修复 SHaRC 关闭仍提前分配缓存、普通显示仍保留大型几何调试缓冲，以及解析光照路线仍创建环境／灯光烘焙资源的问题。通用光照、SHaRC、SR/RR、FG 和几何调试仍保留；资源按实际使用创建。`pathQualityStatus().allocatedCacheEntries()` 在缓存未分配时返回 0，配置容量仍通过 `quality().cache().entries()` 读取。

原生内存诊断仅在进程显式设置 `RTR_RTXPT_MEMORY_DIAGNOSTICS=1` 时启用，生产默认关闭。具体用法见[工具说明](../tools/README.md)。RAM 工作集、私有提交、独立显存和共享 GPU 内存分别报告，不相加。

环境、太阳和全部 POINT / SPOT / DIRECTIONAL 灯光的变化现在复用驻留几何；同帧事务合并、同值跳过、类型替换、增加／删除、零强度、清空和历史失效均覆盖两条 lighting input。默认路线同时补齐 range、castsShadow、聚光灯锥角与托管方向编码。应用继续使用现有 `EnvironmentState` / `SceneLight` / `SceneTransaction`。后端扩展新增兼容的 `lightingTimings()` 默认方法，报告实际 native 装载、灯光提交／上传和历史失效计数。见[完整实现与验收说明](quality/rtxpt-incremental-lighting-701.md)。

本轮实测结果、制品身份和画面对照记录于[内存修复验收](quality/rtxpt-memory-701.md)。最终包私有提交减少约 816 MiB、独立显存减少约 818 MiB，RAM 工作集未下降；七张画面对照六张完全一致，一张金属运动帧存在小幅差异，不能称全部逐像素无损。149 项构建任务和 17 项正式包预算矩阵通过。性能计时与诊断分开；GPU 初始占用超过 10% 时，不报告绝对帧率。
